# Tutorial 6 — Train a prior

A RAVE model transforms sound: it needs an input. A **prior** is a second, smaller model trained to
*predict* the latent trajectories of your dataset, one step after another. Once embedded in the
exported model, it lets RAVE **generate audio on its own**, continuously, in real time — with a
single "temperature" control for how adventurous it is.

🔊 [Listen to an example generated by a prior trained on a darbouka model](../darbouka_prior.mp3).

**You need:** a trained **variational** RAVE model (`v1`, `v2`, `v2_small`, `v3`...) and the dataset
it was trained on (already preprocessed). A GPU.

> For discrete models (`--config discrete`), use [msprior](https://github.com/caillonantoine/msprior)
> instead. Wasserstein models are not supported by the built-in prior yet (see the end of this page).

## How it works

1. The RAVE encoder turns each training chunk into latent trajectories; only the first PCA
   dimensions are kept (chosen by `--fidelity`, rounded up to a power of two).
2. Each latent value is quantized into 32 bins of a standard normal distribution.
3. A causal WaveNet-like network (10 dilated residual layers) learns to predict the bins of the next
   step from the past steps.
4. At generation time, it samples from its own predictions, step by step; the RAVE decoder turns the
   result into audio. The remaining latent dimensions are filled with noise.

## 1. Train

```bash
rave train_prior \
    --name darbouka_prior \
    --model ~/runs/darbouka_abc123 \
    --db_path ~/datasets/darbouka \
    --out_path ~/runs \
    --fidelity 0.95
```

The prior is written to `~/runs/darbouka_prior_<hash>/`. Always give `--name` (otherwise the run is
called `None_<hash>`).

Choosing the number of modeled dimensions:

- `--fidelity 0.95` (or `0.99`, the default) keeps the PCA dimensions explaining this fraction of the
  latent variance, rounded up to a power of two.
- `--latent_size 8` fixes it directly (also rounded up to a power of two).

Fewer dimensions = an easier task for the prior, but more of the sound is left to noise. 8 to 16 is
a good range for most models.

Other options are the same as for `rave train`: `--device`, `--batch`, `--max_steps` (1M by default),
`--val_every`, `--resume`, `--smoke_test`...

## 2. Monitor

```bash
tensorboard --logdir ~/runs/darbouka_prior_<hash>
```

- `latent_prediction` / `validation`: cross-entropy of the next-step prediction. It should decrease
  and plateau.
- In the *Audio* tab, `generation` examples are rendered at each validation: random latent
  trajectories generated by the prior and decoded by RAVE. This is the best way to judge it.

A few hundred thousand steps are usually enough to get musical results.

## 3. Export RAVE with its prior

```bash
rave export --run ~/runs/darbouka_abc123 --prior ~/runs/darbouka_prior_<hash> --streaming --fidelity 0.95
```

> **Use the same `--fidelity` (or `--latent_size`) as for `train_prior`.** The exported latent size
> must equal the prior's. The defaults differ (`0.95` for export, `0.99` for the prior), so if you
> trained the prior with its default, export with `--fidelity 0.99`. If they do not match, the export
> logs an error and writes the model **without** the prior.

The exported model has an extra `prior` method.

## 4. Play it

### In Max/MSP

```text
[sig~ 0.]                         ← temperature control
 |
[nn~ darbouka_abc123_streaming prior]
 |  |  |  ...                     ← one outlet per latent dimension
[nn~ darbouka_abc123_streaming decode]
 |
[ezdac~]
```

The input of `prior` controls the sampling **temperature**. It is mapped through
`softplus(input) / ln 2`, so:

- `0` gives a temperature of 1: plausible continuations, close to the training data;
- negative values (e.g. `-2`) are colder: more conservative, repetitive;
- positive values (e.g. `2`) are hotter: more surprising, eventually chaotic.

Because the output of `prior` is an ordinary latent signal, everything from
[Tutorial 1](01_max_msp.md#5-play-with-the-latent-space) applies: you can bias, scale or crossfade it
with the output of an `encode` to mix generation and transformation.

### In Python

```python
import torch, torchaudio

model = torch.jit.load("darbouka_abc123_streaming.ts").eval()
frames = 500                                        # latent frames to generate
with torch.no_grad():
    control = torch.zeros(1, 1, frames)             # one value per latent frame; 0 = temperature 1
    z = model.prior(control)                        # (1, latent_size, frames)
    y = model.decode(z)
torchaudio.save("prior.wav", y[0], model.sr)
```

## Troubleshooting

| Problem | Solution |
| ------- | -------- |
| `could not load prior ... Did you use the same fidelity / latent parameters as for training?` | Export with the `--fidelity` / `--latent_size` used for `train_prior`. |
| `prior not implemented for encoder of type ...` | The model is discrete or spherical: use msprior for discrete models. |
| Generations are noise / silence | Train longer; reduce the number of modeled dimensions; check that the RAVE model itself reconstructs well. |
| Generations are monotonous | Raise the temperature; model more dimensions. |

## Note on Wasserstein models

`rave train_prior` builds a `WassersteinPrior` for Wasserstein models, but the default prior
configuration only defines hyper-parameters for `VariationalPrior`, and `rave export --prior` only
knows how to load variational priors. Training a prior for a Wasserstein model therefore requires
overriding the prior's hyper-parameters (`--override "WassersteinPrior.resolution=32"` etc.), and
exporting it is not supported yet.
